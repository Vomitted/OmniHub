Your fan stops while the laptop is still hot.

OmniHub is a replacement for Omen Gaming Hub that fixes it — fan curve control with a safety floor, GPU power and mode, and AMD CPU tuning, through the same BIOS interface the vendor's own app uses.

Windows 10 / 11 · x64 · runs as Administrator

The bug it exists to fix

On some HP Omen and Victus laptops the Default/Balanced BIOS fan table contains a 0% idle entry that can be reached while the machine is still genuinely hot. The fan stops. The laptop keeps heating.

Auto (Curve) mode adds a floor

Past a temperature you choose, the fan is never allowed to command 0% again — no matter what the stock table asks for. That single rule is the reason the rest of this exists.

The fix only holds while OmniHub is running. Closed, crashed, or not yet launched after a reboot, the laptop is back on the stock BIOS curve — including the behaviour above. Turn on Launch when you sign in in Settings so the protection is the default rather than something you have to remember.

What will actually work on your laptop

OmniHub starts and runs on any Windows laptop. How much of it is usable depends on your hardware. Controls your machine cannot drive are disabled and named, not left sitting there pretending.

FeatureNeeds
Temperature, load, clocks, memory, battery healthAny laptop
Power plans, scheduling, MMCSS, timer resolution, process priorityAny laptop
Discrete GPU telemetryNVIDIA GPU
CPU power limits, thermal limit, curve optimizerAMD Ryzen + PawnIO
Fan curve control, GPU TGP unlock, BIOS power limitsHP (hpqBIntM)
Lenovo, Dell and ASUS are not supported. Each exposes a completely different ACPI/WMI interface and there is no cross-vendor standard. The vendor layer is isolated behind one availability check so another backend can slot in — but none ships unverified, because untested code that writes to unknown ACPI methods on someone else's laptop should not exist.

It does not make numbers up

The rule the whole project is built on. No invented fan RPM, no "AI" workload classification, no plausible-looking figure standing in for a reading the hardware could not give. If a value is unavailable, the interface says so.

Every write is read back

Applying a limit re-reads the hardware. The Tuning tab distinguishes a limit the firmware accepted from one it actually enforces — some SMUs return success for limits the vendor firmware then arbitrates away.

No telemetry, no network

Settings are plain JSON in %AppData%\OmniHub. Nothing is sent anywhere. The only network call is the one you ask for when installing the PawnIO driver.

Real fan units

The level sent to the BIOS is a speed target in units of ~100 RPM, not a 0–255 duty cycle. This interface exposes no true tachometer reading, and nothing here invents one.

Installing

Windows will warn you about this download. The build is not code-signed — a signing certificate costs money this project does not have — so SmartScreen shows "Windows protected your PC". That warning is doing its job: it means Microsoft has not seen this file vouched for, not that the file has been inspected and cleared. If you would rather not take that on faith, build from source below. It is the same code and takes about five minutes.

Verify what you downloaded

SHA-256 of OmniHub-v1.0.0-win-x64.zip:

6cb78c59339af91e18eb57ad8c990e625ad2d1f3c25bf88ae30b17dd525bdca6

Get-FileHash .\OmniHub-v1.0.0-win-x64.zip -Algorithm SHA256

Then

  1. Extract the zip somewhere permanent — the app runs from where you put it.
  2. Run OmniHub.exe and accept the UAC prompt. Elevation is not optional: fan and BIOS control go through an elevated WMI session, and the SMU driver refuses unelevated callers.
  3. Open Settings and turn on Launch when you sign in.
  4. On AMD Ryzen, the dashboard offers Install the PawnIO driver if it is missing — needed only for the Tuning tab. Or winget install namazso.PawnIO. No restart; OmniHub retries every ten seconds and tuning comes online on its own.

Building it yourself

winget install Microsoft.DotNet.SDK.10
git clone https://github.com/Vomitted/OmniHub.git
cd OmniHub
dotnet build OmniHub.slnx -c Release

Install the current SDK, not the 8.0 one — the solution uses the newer .slnx format that the .NET 8 SDK cannot parse. It still builds the net8.0 target fine. The app lands at OmniHub.App\bin\Release\net8.0-windows\OmniHub.exe.

On a laptop model nobody has checked

Before trusting curve control, run OmniHub.exe -Probe from an elevated terminal. It dumps the raw fan count, type, level, table, temperature, throttling state and GPU mode exactly as the BIOS reports them, with nothing interpreted on top — the ground truth for confirming the command layout matches before you rely on it.

Known limitations

  • Per-model curve tuning is manual. There is no bundled database of per-model presets.
  • The usable raw fan range (~20–55) is a well-sourced community bound for this HP EC family, not something measured on your unit. The Fans tab has a manual calibration tool that steps through levels so you can find yours.
  • PawnIoAccess.cs is an intentional stub — CPU-package temperature via MSR read needs the PawnIO SDK wired against your installed version.
  • Throttling detection is not independently verified against known-good hardware.
