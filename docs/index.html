What it actually did

Four numbers, measured rather than claimed

Landing pages assert. This is a tool that talks to firmware, so here is what came back when it did — including the part where the firmware fought it.

82.8 → 72 °C Average die temperature after dropping the SMU thermal limit from 85 °C to 80. The one tuning knob on this platform that the firmware actually enforces.
75 W GPU ceiling with Custom TGP and Dynamic Boost both on — up from 60 W with both off. The card's maximum, and it takes both flags to reach it.
~90 s How long the firmware waits before quietly reverting the power unlock. A 5-second re-assert holds it; 6 of 8 samples stayed at the ceiling.
0.3–1.1 % CPU used by OmniHub itself, around 200 MB resident, 2.45 s from launch to first reading. It watches the machine without becoming the load.
Measured on one machine — an HP Victus 15 fb2999ax: Ryzen 5 8645HS, RTX 4060 Laptop. Not a fleet, not a benchmark suite, not a claim about your hardware. Different silicon and a different BIOS will answer differently, which is exactly why the app reads every value back instead of assuming the write landed.
The GPU ceiling

Two flags, four ceilings, and they stack

HP exposes Custom TGP and Dynamic Boost as separate switches with no documentation of what either is worth. Sweeping all four combinations and reading the sustained power back gives the answer: +5 W and +10 W, and they add.

This is why the app latches the unlock rather than setting it once. The firmware reverts CustomTgp on its own after about ninety seconds, so every preset, profile and mode button is clamped while the latch is on, and the value is re-asserted on a five-second interval.

Mechanism

What it is actually talking to

No abstraction layer invented for a landing page. These are the interfaces, and they are the same ones OmenMon, OmenCore and Omen Gaming Hub itself use.

The BIOS

HP's WMI method, reached through an elevated session. Fan mode, fan level, GPU power flags and mode all go through it.

namespace root\wmi
class hpqBIntM
instance ACPI\PNP0C14\0_0

The fan units

The byte sent to the EC is a speed target in hundreds of RPM, not a 0–255 duty cycle. The UI's percentages map onto the usable band, not onto the byte's full span.

raw × 100 = RPM
usable band ~20–55 (2000–5500 rpm)
tachometer readback: not exposed

The die sensor

Read from the SMU through PawnIO, a signed ring-0 driver. Finer and more honest than the single coarse ACPI zone, which on this board reports a malformed critical point.

THM_TCON_CUR_TMP 0x00059800
resolution 0.125 °C
driver PawnIO (optional)
Where it refuses. Curve Optimizer returns 0xFF on this machine even at an offset of zero, while invalid command IDs return 0xFE — so the mailbox recognises the command and specifically declines it, because PBO is disabled in firmware. The app reports that as refused rather than showing an undervolt it did not apply. Nothing here writes to an ACPI method it has not verified, which is also why Lenovo, Dell and ASUS backends do not ship.
Getting it running

Install, and check what you downloaded

Windows will warn you about this file. It is not code-signed — a certificate costs money this project does not have — so SmartScreen shows "Windows protected your PC". That warning means Microsoft has not seen this file vouched for, not that it has been inspected and cleared. Verifying the checksum below tells you the file arrived intact; it does not tell you to trust it. Building from source settles both.

SHA-256 of OmniHub-v1.0.0-win-x64.zip, built from commit b3bb84f:

fde03a7c3078c42643abd41f1502a627b9ca8b029f66bc6e0b7f5efaecb0faf6

Get-FileHash .\OmniHub-v1.0.0-win-x64.zip -Algorithm SHA256
  1. Extract somewhere permanent — it runs from where you put it, no installer.
  2. Run OmniHub.exe and accept the UAC prompt. Elevation is not optional: the WMI session needs it and the SMU driver refuses unelevated callers.
  3. In Settings, turn on Launch when you sign in. This matters more than it sounds — closed or not yet started, you are back on the stock curve, including the behaviour at the top of this page.
  4. On Ryzen, the dashboard offers Install the PawnIO driver when it is missing, or winget install namazso.PawnIO. No restart; the app retries every ten seconds and tuning comes online by itself.

Or build it

winget install Microsoft.DotNet.SDK.10
git clone https://github.com/Vomitted/OmniHub.git
cd OmniHub
dotnet build OmniHub.slnx -c Release

Install the current SDK, not 8.0 — the solution uses the newer .slnx format that the .NET 8 SDK cannot parse. It still builds the net8.0 target.

On hardware nobody has checked. Run OmniHub.exe -Probe from an elevated terminal before trusting curve control. It dumps raw fan count, type, level, table, temperature, throttling state and GPU mode exactly as the BIOS returns them, with nothing interpreted on top — the ground truth for confirming the command layout matches your board before you rely on it.
Not solved

What this does not do

A tool that writes to your firmware should be specific about its edges.

  • The protection is not persistent. It holds only while the app runs. Crashed, closed, or pre-login, the stock curve is back.
  • No per-model preset database. Curve tuning is manual, via the Fans tab or the built-in calibration sweep.
  • The 20–55 raw band is borrowed, a well-sourced community bound for this HP EC family — not measured on your unit. The calibration tool exists to find yours.
  • Curve Optimizer is refused by firmware on this machine, and the app says so rather than pretending an undervolt applied.
  • PawnIoAccess.cs is a deliberate stub. MSR package temperature needs the PawnIO SDK wired against your installed version.
  • Throttling detection is unverified against known-good hardware.
